# 沉浸模式設計

## 概念卡

| | |
|---|---|
| Idea | 沉浸模式就是你在 Ado 演唱會的座位：MV 是舞台大螢幕，歌詞是螢幕下方的字幕，畫面最下面是整片手燈海 |
| Metaphor | 演唱會場館：熄燈、舞台螢幕、字幕、台下的手燈 |
| Signature | 「交給觀眾」：播到大合唱的句子，舞台螢幕退暗，歌詞發出這首手燈色的光，台下手燈海整片舉高、燈光轉向觀眾席；唱完螢幕再亮回來 |
| Emotion | 開演前場燈熄掉的那一秒 |
| Motion verb | 像場燈一樣「暗下、亮起」：慢進慢出，不彈跳 |
| Screenshot | 大合唱時：暗下來的舞台螢幕、置中發光的那句歌詞、底下整片同色的手燈 |

錨點：這個網站本來就有每首的手燈色（PEN）、拍點（BEAT）和逐行「大合唱」標記，這個概念只有應援指南做得出來。

其他兩個候選：
- 歌詞海報（大字置中、背景取 MV 主色）：跟一般音樂 App 的歌詞畫面一樣，可攜性太高，不選。
- 剪影箱（影片框成發光的箱子）：太依賴特定演出的舞台造型，不選。

## 系統

- **色彩**：場館黑 `#05060a`（底）、字 `#f4f6fb`、次要字 `rgba(244,246,251,.5)`、更淡 `rgba(244,246,251,.32)`、細線 `rgba(255,255,255,.08)`、強調色＝這首的手燈色 `--mesh-c1` / `--mesh-c2`（`updateAmbientColors` 設在 body 上）。
- **字**：沿用站上的日文字體。現在這句 700 字重、字距 -0.015em；其他句小一號、半透明。
- **形狀**：舞台硬體（螢幕）直角（3D 場館沒載入時 6px 圓角）；介面（提示膠囊、頂欄）全圓膠囊。
- **動態**：進入時先熄燈（黑幕 260ms 淡入），換版面後黑幕 700ms 淡出，同時螢幕「開機」（從全黑、過亮再回正常）。離開時黑幕短暫淡入淡出，像場燈亮起。大合唱的退暗 1.1 秒進、1.4 秒出。
- **閒置**：暫停時舞台後方的光暈仍慢慢呼吸（14 秒一輪），不需要播放也看得出是活的。
- **減少動態**：不載入 3D 場館（用 2D 燈光畫布），沒有黑幕轉場和開機動畫；大合唱時只把螢幕調暗。

## 版面

```
電腦                                    手機
┌───────── 頂欄（3.5 秒沒動就淡出）───┐   ┌─ 頂欄 ─┐
│      ┌──────── 舞台螢幕 ────────┐     │   │ 螢幕(滿版)│
│      │                          │     │   │ (提示膠囊)│
│      └──────────────────────────┘     │   │ 前一句   │
│        (圖示 拍手 │ 3 秒後 唱「…」)    │   │ 現在這句 │
│              前一句（淡）              │   │ 下一句   │
│            現在這句（大、置中）         │   │ 手燈海   │
│              下一句（淡）              │   └────────┘
│  ///// 手燈海（畫布，跟著拍點擺動）///// │
│            （工具列，閒置淡出）         │
└────────────────────────────────────────┘
```

螢幕大小用剩下的高度算：`畫面高 − 230px（頂欄、提示、工具列）− max(180px, 26dvh)（至少 3 句字幕）`，矮的筆電螢幕也不會把字幕擠掉。
字幕清單上下各留半個框高的空白（放在 `#lines` 上，不放在捲動框上，不然捲動框縮不回來），現在這句永遠在框的正中間。

## 3D 場館

原始碼 `tools/stage3d/venue.js`，打包成 `assets/stage3d.js`（three.js 只打包用到的部分）：

```bash
cd tools/stage3d && npm install && npm run build
```

第一次開沉浸模式才用 `import()` 載入；減少動態、沒有 WebGL、載入失敗、或「顯示」裡關掉燈光效果時，照舊用 2D 的燈光畫布（`#fx`）。

### 透視規則

YouTube 影片是平的 DOM，沒辦法放進 3D 裡，所以 3D 場館要配合影片，而不是反過來：

1. **攝影機不俯仰、不翻滾**，只看正前方。構圖靠「鏡頭位移」（非對稱視錐），垂直線永遠是垂直的，不會有往上看的梯形變形。
2. **舞台螢幕和視線垂直**，影片疊上去剛好是長方形，跟 3D 外框完全對齊。
3. **視窗投影**：瀏覽器畫面就是舞台螢幕那個深度的一扇窗。攝影機為了視差移動時（游標＋很慢的晃動，最多左右 0.9、上下 0.4 公尺），視錐跟著換，螢幕那個深度的東西永遠釘在原位；近的觀眾移動得多、遠的燈架移動得少。
4. **焦距用畫面對角線算**（距離＝對角線 × 0.78，約 35mm 鏡頭），直拿、橫拿、寬螢幕的透視強度差不多，不會在手機上變成廣角變形。
5. **攝影機正對螢幕中心、眼睛在螢幕中間的高度**：地平線落在螢幕中段，你坐在看台上往前看，觀眾席往下鋪到畫面底。
6. **最近的觀眾在 1/3 距離外**，太近的手燈會變成一條條大光棒；離鏡頭 9–16 公尺的手燈慢慢淡掉，像相機的淺景深。

### 場景

- 舞台：螢幕底下的深色舞台、前緣 LED 燈條（一格 50 公分，顏色沿著燈條流動循環：這首的手燈色；單色手燈的歌改成彩虹）、兩側 LED 柱、吊掛喇叭、燈架。
- 燈光：燈架的燈往觀眾席掃（打到地板為止，不穿過鏡頭）、舞台前緣的射燈往上打成扇形、場館兩側高處的追蹤燈打向舞台中間。全部用圓錐＋邊緣淡出的著色器，不用後製。
- 觀眾：一人一個頭肩剪影＋一支手燈，一排一排站好（排距 62 公分、座位 50 公分、隔排錯開），最多 2400 人（手機 1200），用 instancing 一次畫完。
  - 手燈以手為支點**前後**擺（往舞台倒、再往回），每拍換一個方向，全場同步、每個人有一點點偏差。
  - 顏色跟網站送給 PenlightSync 的一樣：`app.js` 的 `lampLook()` 照搬 PenlightSync「網站」取色模式（`SiteLightEvaluator`，自動節奏）的規則算出現在輪到第幾色（一般段落每 2 拍換、拍手／喊聲／跳躍或 135 BPM 以上每拍換、副歌高潮 8 拍內每半拍換、沒有拍點每 4 秒換；安靜聽亮度減半）。多色的歌再依「排＋座位」錯開，鄰座交錯不同顏色。頭頂的邊光也是自己手燈的顏色。
  - 拍手（含反拍拍手）：手燈直直舉高不擺，拍手那一拍往下一頓、亮一下（反拍只在第 2、4 拍）。跳躍：全場跟著拍子一起彈。
- 大合唱（`raise`）：手燈舉高變亮、燈架的燈轉向觀眾席、LED 柱和剪影的邊光變亮、螢幕背後的光變暗。
- 字幕後面墊一層暗的放射漸層，手燈再亮也讀得到。

注意：three.js 的加法混色（AdditiveBlending）會再乘一次 alpha，著色器輸出顏色時不要先乘 alpha，不然會變成 alpha²，暗到看不見。

除錯：網址加 `?debug3d` 會把場館掛在 `window.__venue`（`debug.scene`、`debug.camera`、`debug.beams`、`debug.L`）。
